# 리서치 카드 : 승조

구현에 들어가기 전에 **선택지를 모아 비교한 것**을 남긴다. 읽은 글 링크만 모아 둔 건 리서치가 아니다 : 선택지가 2개 이상, 출처 링크가 1개 이상, "고른 것과 버린 것" 이 있어야 한 장으로 친다.

범위는 [`docs/harness/README.md`](../harness/README.md) 와 같다(승조 담당 파트). 결정으로 굳어지면 [`docs/design/01-decisions.md`](../design/01-decisions.md) 에 4요소(채택 · 기각 · 사유 · 되돌림)로 옮기고, 카드에는 번호를 적는다.

## 규칙

- 파일 이름 `YYYY-MM-DD-<주제>.md`. 코드와 **같은 PR** 에 넣는다
- 묻기 전에 "알고 있던 것" 세 줄을 먼저 적는다 : 질문이 저절로 좁아진다
- 답은 **출처로 확인**한다. 순서: 공식 문서 → 오픈소스 코드 → 기술 블로그. 링크를 못 찾은 주장은 **미확인**이라고 적는다
- AI 가 틀렸던 것도 지우지 않고 남긴다. 그게 "어떻게 검증했나" 의 답이 된다
- 카드 끝에 이 조사에서 나온 면접 질문을 적는다

## 틀

```markdown
# [주제]

- 날짜 / 걸린 시간 / 관련 이슈
- 알고 있던 것 (세 줄):
- 알고 싶었던 것:

## 물은 것
프롬프트 원문 또는 프롬프트 로그 링크.

## 나온 선택지
| 방법 | 장점 | 단점 | 쓰는 곳(출처 링크) |
|---|---|---|---|

## 우리 데이터로 확인한 것

## 고른 것과 이유

## 확인 못 한 것

## 여기서 나온 면접 질문
1.
```
