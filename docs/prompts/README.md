# 프롬프트 로그 — 승조

AI 에게 무엇을 어떻게 물었고 무엇이 나왔는지 남긴다. 잘 된 것과 안 된 것을 **둘 다** 남긴다 — 안 된 것에서 "프롬프트의 어느 칸이 비어서 생긴 문제인가" 가 나온다.

범위는 [`docs/harness/README.md`](../harness/README.md) 와 같다(승조 담당 파트). 과제 전형에서 프롬프트를 내라고 하면 그대로 낼 수 있게, 남이 읽어도 되게 쓴다.

## 규칙

- 파일 이름 `YYYY-MM-DD-<작업>-<이슈번호>.md`. 코드와 **같은 PR** 에 넣는다 — 나중에 몰아 쓰면 안 쓴다
- 프롬프트는 **원문 그대로**. 고쳐 쓰지 않는다. 짧았으면 짧은 채로
- 다섯 칸(목표 · 배경 · 범위 · 제약 · 완료 기준) 중 무엇이 프롬프트에 있었고 무엇이 다른 곳(이슈 · `AGENTS.md` · 가이드)에 있었는지 적는다
- 숫자(토큰 · 왕복 · 시간)는 잴 수 있었을 때만. 못 잰 건 비운다

## 틀

```markdown
# [날짜] [작업 이름]

- 관련 PR / 이슈:
- 쓴 도구: (예: /ralplan → /ralph, 서브에이전트 2개)

## 프롬프트
(원문 그대로)

## 다섯 칸은 어디에 있었나
| 칸 | 프롬프트에 | 다른 곳에 |
|---|---|---|

## 결과
- 한 번에 됐나: 예 / 아니오
- 고쳐 물은 횟수:
- 무엇이 잘못 나왔나:
- 고쳐 물은 말:

## 다음에 바꿀 점
(프롬프트의 어느 칸이 비어서 생긴 문제였나)

## 숫자 (잴 수 있었으면)
총 토큰 / 왕복 횟수 / 걸린 시간
```
