## 다섯 칸은 어디에 있었나

프롬프트는 한 줄이다. 그런데 한 번에 거의 맞게 나왔다. 다섯 칸이 프롬프트 바깥에 **이미 있었기** 때문이다.

| 칸 | 프롬프트에 | 다른 곳에 |
|---|---|---|
| 목표 | "I" 한 글자 | 이슈 `#83` 본문 — 왜 비어 있고(에이전트가 `peer.service` 를 안 넣음) 왜 적재에서 채워야 하는지(MV 가 insert 시점에 `EXTERNAL` 로 굳힘) |
| 배경 | 없음 | `AGENTS.md` §5 의 `#66`(같은 "PG 조회 + 캐시" 꼴) · §6 의 `peer_service` 줄, 앞 세션 대화 |
| 범위 | 없음 | `AGENTS.md` §2 — 모듈끼리 `:common` 만 의존, 표 주인 규칙 |
| 제약 | 없음 | `AGENTS.md` §2 — Kotest BehaviorSpec, 마이그레이션 규칙; 메모리 — DDD(포트 · 어댑터 분리), 한국어 설명 주석 |
| 완료 기준 | 없음 | ralph 가 가이드 .md 의 "확인 순서" 를 완료 기준으로 썼다 — 단위 테스트 · PG 캐시 테스트 · telemetrygen 관통 · `server_map_1m` 에 `SERVICE` 간선 |

즉 **이 한 줄 프롬프트는 "다섯 칸을 안 쓴" 게 아니라 "다섯 칸을 파일에 미리 써 둔" 경우**다. 이슈와 `AGENTS.md` 가 없었으면 이 한 줄로는 안 됐을 것이다.

## 결과

- 한 번에 됐나: **아니오** (구현은 한 번에, 리뷰에서 1건 수정)
- 고쳐 물은 횟수: **1**
- 무엇이 잘못 나왔나:
  1. **SERVER 스팬에도 `peer_service` 가 채워졌다.** 관통 시험 도구(telemetrygen)가 `--telemetry-attributes` 를 SERVER 스팬에도 붙이기 때문. 실제 에이전트의 SERVER 스팬 `server.address` 는 자기 주소라, 채우면 "자기 자신으로 가는" 가짜 간선이 생긴다. 리뷰 단계에서 나왔다
  2. (고쳐 묻지는 않았지만) 테스트 스팬에 시각을 안 넣어 1970년이 됐고, `spans` TTL(93일)이 insert 시점에 적용돼 **넣는 즉시 사라졌다.** 로그는 "1줄 적재", 조회는 0줄. 추적해서 원인을 찾았다
- 고쳐 물은 말: 리뷰 결과를 받고 "채우기를 CLIENT · PRODUCER 스팬으로 한정" 으로 보강. `CALLER_KINDS = setOf("CLIENT", "PRODUCER")`

## 설명 단계에서 고쳐진 것

구현 뒤 "이게 뭘 하는 건지" 를 설명받는 자리에서 내가 **"스팬이 어디서 왔는지"** 라고 정리했는데, 맞는 말은 **"어디로 갔는지"** 였다. `peer_service` 는 호출 **대상**이다 — 서버맵 화살표의 머리 쪽. 코드는 맞았고 내 이해가 틀렸던 것이라 이 자리에서 바로잡았다. 이런 게 남아야 면접 답이 된다.
