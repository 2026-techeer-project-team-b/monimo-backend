# 기능 명세 목록 (FN-1~61)

핵심기능 5축(Agent·트레이스 추적 / 알람 / 시스템 메트릭 / 히트맵·스캐터 / config UI) + 파수꾼(자기 감시). 계층 컬럼이 `화면`이면 FE(프론트엔드) 작업, 그 외(에이전트/파이프라인/저장소/API/외부)는 백엔드·인프라 작업이다.

## 2. 알람 기능 (FN-24~32)

| FN | 기능명 | 설명 | 화면(FE)/백엔드 구분 | Phase |
|---|---|---|---|---|
| FN-24 | 경보 규칙 CRUD | 지표·조건·임계값·지속시간·심각도·수신 채널을 PostgreSQL에 저장하고 수정한다. CRUD API와 PG 쓰기는 API 서버가 제공하고(화면은 API 서버 하나만 부른다), 탐지는 이 표를 10초에서 30초 주기로 읽기만 한다(ADR #39). 알림 채널·규칙-채널 연결도 같은 주인이다. | 백엔드(API) | 1a |
| FN-25 | HTTP 상태코드 대역 조건 (4xx / 5xx) | 4xx 비율, 5xx 비율, 특정 코드(500·503) 발생 횟수를 기본 제공 규칙 유형으로 만든다. 4xx·5xx 비율은 metric_kind 4XX_RATE·5XX_RATE로 1a에 지원하고, 특정 코드(500·503) 횟수는 Phase 2로 미룬다(ADR #40). | 백엔드(API) | 1a |

| FN-27 | 주기 평가 스케줄러 | 등록된 규칙을 고정 주기로 돌면서 API 서버에 물어보고 조건 충족 여부를 판정한다. Kafka 컨슈머가 아니다. 규칙 자체는 PG에서 10초에서 30초 주기로 읽기만 하고(쓰기는 API 서버 몫), 탐지가 쓰는 표는 alert_events뿐이다(ADR #39). | 백엔드(API) | 1a |
| FN-28 | 발화·해제 상태 관리 | 연속 N회 충족해야 발화하고 M회 정상이어야 해제한다. 발화 중인 경보는 다시 발화하지 않는다. | 백엔드(API) | 1a |
| FN-29 | 데이터 침묵 규칙 | 특정 서비스의 지표가 일정 시간 이상 아예 들어오지 않으면 이상으로 판정한다. 에이전트 생존 판정도 이 규칙으로 한다 — AGENT_DOWN 규칙이 'CH에 해당 에이전트 데이터가 90초 동안 없음'을 1분 주기로 평가해 agents.status를 DOWN으로 바꾸고 알린다. 같은 서비스의 에이전트가 전부 DOWN이면 1건으로 묶는다(ADR #35). | 백엔드(API) | 2 |
| FN-30 | 알림 채널 전송 | 발화를 받아 Slack으로 보낸다. 채널 어댑터 구조로 만들어 이메일·웹훅·PagerDuty를 나중에 끼울 수 있게 한다. | 백엔드(API) | 1a |
| FN-31 | 알림 이력과 중복 억제 | 보낸 알림을 PostgreSQL에 남기고 같은 경보의 반복 발송을 일정 시간 묶는다. | 백엔드(저장소) | 1a |
| FN-32 | 전송 재시도와 실패 자체 경보 | 채널 전송이 실패하면 재시도하고, 계속 실패하면 그 사실 자체를 다른 경로로 알린다. | 백엔드(API) | 2 |
