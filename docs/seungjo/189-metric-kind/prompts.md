4. `즉 GC 데이터를 가져올 때 이번엔 얼마가 걸렸는지를 표에 기록하는ㄷ 그 때 자바 기본 설정 때문에 총합이 나간다 그래서 해결법이 현재값과 총합을 나눠서 각각에 데이터가 들어가게 하는 거다?`

## 팀에 보낸 정리 (7번에서 고친 판)

```
[누적지표 이슈]
누적해서 쌓는 건 우리가 아니라 에이전트 안의 OTel SDK
우리는 그 SDK 가 보내준 총합을 받은 그대로 넣고 있었다

결과물 : 분당 GC 시간 (원하면 분당 GC 횟수도 같은 방법)
에이전트 : OTel Java 기본값이 cumulative(누적) 라서 매 내보내기마다 켜진 뒤 총합(sum) + 총횟수(count) 를 보냄
적재 : 그 총합을 그대로 저장, 단 A 방법에서는 "이건 총합" 꼬리표를 같이 저장
조회 : 꼬리표가 총합인 시계열은 시간순으로 읽으면서 앞 값을 빼서 "이 1분에 얼마" 로 계산해서 보내기

빼기 할 때 조건 두 개
- 같은 파드 + 같은 시계열끼리만 뺌, 파드가 다르면 총합이 서로 다르니 섞으면 안 됨
- 뺀 값이 음수면 파드 재시작이라 그 구간은 건너뜀 (또는 지금 총합을 그대로 씀)

경보도 같은 식
- "분당 GC 시간이 500ms 넘으면" 을 총합이 아니라 뺀 값에 걸어야 함
- 그래서 노션의 남은 질문이 "경보가 직접 뺄지, 조회 API 가 뺀 값을 줄지" 임
```

## AI 가 대신 정한 것 (사용자가 따로 말하지 않은 것)

- 칸을 둘(`metric_type` · `is_counter`)로 한 것과 이름 `is_counter`
- 롤업 둘에 `is_counter` 를 흘린 것
- 옛 줄 · 가짜 데이터를 안 건드린 것
- temporality 가 UNSPECIFIED 면 0 으로 둔 것
