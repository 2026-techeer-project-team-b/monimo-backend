# `#159` 에이전트 인증을 mTLS 로 붙인다 : 수집기 포트에서 직접, 도장만 보고, 두 단계로 켠다

- 이슈 `#159` · 「에이전트 인증은 수집기 포트 mTLS」 결정 · 브랜치 `feat/159-agent-mtls`
  - `AGENTS.md` §6 "에이전트 mTLS 인증이 없다" 행을 지운다
- 조사는 [`research.md`](research.md) 9단계에 있다
  - 이 글은 그 요약과 확인 결과다
- 짝 이슈
  - 쇼핑몰 쪽은 monimo-shop `#40` (코드 0줄)
  - 배포 쪽은 monimo-deploy `#11` (문서만)

## 문제

- 수집기가 신호를 받는 포트(4317)가 **평문이고 인증이 없다**
  - 그 주소에 닿는 누구나 가짜 스팬 · 지표 · 로그를 넣을 수 있다

```
ADR #21 ④     mTLS 를 이미 채택했다. 되돌림으로 "1b 에서" 로 미뤘다
ADR #62       1b 를 열었다. 그런데 ⑤ 가 "입구에서 TLS 를 끝내고 수집기엔 평문으로" 라고 적었다
AGENTS §6     "에이전트 mTLS 인증이 없다" 가 2026-09-29 부터 올라와 있었다
```

### 진짜 나쁜 것은 양이 아니라 파수꾼 위조다

- 처음 이슈 본문은 "카나리 표식을 붙이면 샘플링까지 우회한다" 를 문제로 적었다
- 되물음에서 바로잡혔다
  - trace ID 는 보내는 쪽이 고르므로 **샘플링은 원래 방어가 아니다**
- 핵심은 표식(`trace_state` 의 `monimon=canary`)이 공개 레포에 적힌 기본값이라는 것이다
  - 누구나 붙일 수 있다
  - 붙이면 "스택이 살아 있다" 는 판정을 가짜로 만들 수 있다
- 죽은 스택이 산 것처럼 보이는 것이 가장 나쁘다

## 선택지

- 큰 결정이 둘이었고, 그 뒤 여섯 묶음이 따라왔다
- 전체 표와 버린 이유는 [`research.md`](research.md) 4절 · 5절 · 7절에 있다
- 표 속 번호 : `#62` ⑤ 는 「EKS 배포 기반 : Spot · NAT · Traefik」 결정의 ⑤, `#149` 는 파드 명부 주소 칸(`agents.ip`), `#16` 은 수집기가 OTLP 를 풀지 않고 Kafka `raw` 에 넣는 약속, `#119` 는 ClickHouse 마이그레이션 수단

| 무엇 | 고른 것 | 버린 것과 이유 |
|---|---|---|
| 바깥 에이전트를 받나 | **안 받는다** | 받기 : 지금 그 경로가 없고, 받으면 입구와 수집기를 둘 다 막아야 한다 |
| TLS 를 어디서 끝내나 | **수집기** (위 결정이 정해 준다) | 입구(`#62` ⑤ 원안) : 쇼핑몰은 클러스터 안에서 서비스 이름으로 붙어 **입구를 안 지난다.** 입구에 걸면 안에서 쏘는 것을 못 막고, 수집기가 보는 주소가 입구 주소가 되어 `#149` 가 깨진다 |
| 신분증 수 | **서비스마다 한 벌** (4벌 + 점검용 1) | 한 벌 공유 : 하나 새면 전부 재발급 / 파드마다 : 손으로 못 만든다 |
| 검사 범위 | **도장만** | 수집기가 신호를 열어 이름까지 : `#16` 약속이 깨지고 지표 · 로그를 새로 열어야 한다 |
| 유효기간 | **길게(10년 · 5년) + 재시작** | 짧게 + 다시 읽기 : 손으로 또 만들어야 하고 다시 읽는 장치는 시간이 없다. 대신 **만료 경로를 시험으로 밟는다** |
| 열쇠 보관 | **켤 때 compose 가 만든다** | 레포 : 다섯 레포가 전부 공개 / 각자 돌리기 : `#119` 가 두 번 시켜 본 비용 |
| 거절 감지 | **붙어 있는 수** | 거절 횟수 : 악수 단계라 **셀 수 없다**(확인). 셀 수 있는 척하는 지표보다 없는 지표가 낫다 |
| 켜는 순서 | **두 단계** (`optional` → `require`) | 한 번에 : 빠뜨린 쪽이 조용히 멈춘다 |

### 돈과 일을 갈라 봐야 했다

- "입구에서 끝내면 NLB 가 드는데 왜 수집기에서 끝내는 쪽이 더 비싸냐" 는 질문에 걸렸다
- 입구 안이 더 싼 것이 아니라, 수집기 안이 **일**이 더 드는 것이었다
  - 수집기 인증서 관리
- NLB 는 화면 · API 때문에 어차피 필요하다
- 2.4 를 돈과 일로 갈라 다시 적었다

## 결정

- 「에이전트 인증은 수집기 포트 mTLS」 결정 에 4요소로 있다
- 바꾼 것은 **수집기 하나와 compose · 스크립트**, 그리고 다른 레포 둘의 설정 · 문서다

| 어디 | 무엇 |
|---|---|
| `collector` | 서버를 자격증명 받는 꼴로(`Grpc.newServerBuilderForPort`) · 요구 수준 설정 하나(`tls.client-auth` = `none` · `optional` · `require`, 기본 `none`) · 파일 셋은 기동 때 한 번 읽고 못 읽으면 **기동 실패** · 기동 로그에 요구 수준과 경로 · 게이지 둘(연결 수 · 에이전트 수, 태그 `auth`) |
| `compose.yaml` | `otlp-certs` 일회성 컨테이너(멱등) · 수집기 `/certs` 마운트 · `COLLECTOR_TLS_CLIENT_AUTH` |
| `scripts/certs/` | 생성 스크립트와 이미지. 기관 10년 · 수집기 · 손님 5벌(쇼핑몰 넷 + `check`) · 만료된 손님 1벌 · 쇼핑몰용 `env/*.env`. 시험도 같은 스크립트를 임시 폴더에 돌린다 |
| 점검 스크립트 둘 | `.env` 의 요구 수준을 읽어 telemetrygen 을 평문 또는 `--mtls` 로 보낸다 |
| monimo-shop `#40` | compose `env_file` 로 https 주소와 파일 셋 · `/certs` 마운트. `.env` 한 줄(`MONIMO_OTLP_CERTS_DIR`)로 켠다. **코드 0줄** |
| monimo-deploy `#11` | `#62` ⑤ 에서 수집기 gRPC 통로를 뺀다. **문서만** |
| 적재 처리기 · 조회 · 화면 | **0줄.** Kafka 뒤는 TLS 와 무관하다 |

### 프롬프트에 없던 것 둘

- **에이전트 수 게이지**
  - 프롬프트 ④ 는 연결 수 하나였다
  - 관통에서 연결 수가 12 → 8 로 흔들리는 것을 보고(아래) 주소를 묶은 `monimo.collector.otlp.agents` 를 더했다
  - "넷이 다 붙었나" 에 답하는 쪽은 이것이다
- **점검용 신분증 `check`**
  - 프롬프트 ⑦ 의 목록은 쇼핑몰 넷이었다
  - 점검 스크립트가 4317 에 직접 쏘는 유일한 다른 손님이라 한 벌을 따로 뒀다
  - 쇼핑몰 것을 빌리면 게이지에서 가를 수 없다

## 장애가 나면

| 무슨 일 | 어떻게 되나 |
|---|---|
| 신분증 기간이 지났다 | 그 에이전트가 악수에서 끊기고 `agents{auth=mtls}` 가 하나 준다. 에이전트 로그에 `Failed to export spans`. **신호가 어느 날 조용히 끊기면 이것부터 본다.** 갱신은 `certs/` 를 지우고 compose 를 다시 켠 뒤 수집기와 에이전트를 재시작하는 것이다(파일은 기동 때 한 번만 읽는다) |
| 수집기 파일이 없거나 못 읽는다 | **기동하지 않는다.** `Failed to start bean 'otlpGrpcServer'` 와 어느 파일인지. 평문으로 대신 뜨지 않는다 |
| 에이전트에 신분증을 안 심고 `require` 로 올렸다 | 그 에이전트만 떨어진다. 나머지는 그대로. `optional` 에서 `agents{auth=mtls}` 가 쇼핑몰 수인지 먼저 보는 것이 두 단계의 뜻이다 |
| 에이전트가 아직 평문이다 | `optional` 에서도 못 붙는다. 전환에 에이전트 재시작 한 번이 반드시 든다 (아래 "조사가 바로잡힌 것") |
| 다른 기관 도장 · 이름이 같은 가짜 | 악수에서 끊긴다. 이름은 안 보고 도장만 보므로 이름이 `shop-order` 여도 도장이 다르면 안 된다 |
| 신분증 하나가 샜다 | 그 신분증으로 누구나 붙는다. 이름 검사(적재 처리기 비교)를 올린다 : 「에이전트 인증은 수집기 포트 mTLS」 결정 되돌림 ② |
| 게이지를 읽는 자리가 바뀐다 | `ServerTransportFilter` · `Grpc.TRANSPORT_ATTR_SSL_SESSION` 은 실험 API 다. 바뀌면 게이지가 먼저 틀린다 : 되돌림 ⑤ |
| 거절이 몇 번인지 알고 싶다 | **못 센다.** 필터가 악수 뒤에만 불린다. 대신 붙어 있는 수가 줄어든 것을 본다 |

## 어떻게 확인했나

### 관통 (로컬 compose, 2026-10-13)

- 쇼핑몰 넷과 수집기로 꺼짐 → `optional` → 신분증 심기 → `require` 를 밟았다
- 게이지는 수집기 관리 포트의 `/actuator/metrics/monimo.collector.otlp.{connections,agents}?tag=auth:{plaintext,tls,mtls}`

| 단계 | 수집기 | 쇼핑몰 | `connections` | `agents` | 에이전트 오류 |
|---|---|---|---|---|---|
| 1 꺼짐 | `none` | 평문 | plaintext 12 | (옛 이미지) | 0 |
| 2 올림 | `optional` | 평문 그대로 | **0** | 0 | 넷 다 `Failed to export spans` |
| 3 심기 | `optional` | `MONIMO_OTLP_CERTS_DIR` 켬 | mtls 12 | : | 0 |
| 4 반드시 | `require` | 그대로 | mtls 8 | **mtls 4** | 0 |
| 5 하나 빼기 | `require` | inventory 만 신분증 뺌 | mtls 6 | **mtls 3** | inventory 만 |
| 6 되돌림 | `require` | 넷 다 | mtls 8 | mtls 4 | 0 |

- **4 단계에서 명부 네 줄의 주소가 `docker inspect` 와 정확히 일치**
  - gateway `.14` · order `.13` · payment `.12` · inventory `.8`
  - payment · inventory 는 재생성으로 주소가 바뀌었는데 `#149`(파드 명부 주소 칸)가 TLS 뒤에서도 고쳐 넣었다
- 주문 `POST /api/orders` 201 × 3 (3 · 4 단계)
- 수집기 열쇠 경로를 `/certs/nope.key` 로 주고 띄우니 `Failed to start bean 'otlpGrpcServer'` · `읽을 수 없는 파일이 있다 : [수집기 열쇠(server-key)=/certs/nope.key]` · 종료 코드 1
- `check-wiring.sh` · `check-pipeline.sh` : `none` · `optional` · `require` 세 번 다 통과 (telemetrygen `--mtls --ca-cert --client-cert --client-key`)
- 인증서 생성
  - 호스트 1.0초
  - 컨테이너(alpine openssl 3.3) 같은 결과
  - 두 번째 실행은 "이미 있음, 아무것도 안 했다"

### 시험

| 무엇 | 어디 |
|---|---|
| 요구 수준 글자 셋 → grpc `ClientAuth` · 모르는 글자는 묶기 실패 · 켜 놓고 파일 없으면 실패(어느 파일인지) · `none` 이면 파일을 안 읽는다 | `collector` `OtlpGrpcPropertiesTest` |
| 게이지 더하고 빼기 · 같은 주소 연결 둘 = 에이전트 1 · 주소 없는 연결은 에이전트에 안 센다 · 준비된 적 없는 끊김은 0 | `collector` `OtlpConnectionGaugeTest` |
| `require` : 신분증 손님 세 신호 통과 + `#149` 메모 그대로 · 신분증 없음 · 다른 기관 · **만료** · 평문 전부 끊김 · 게이지 1 → 0 · 거절은 게이지를 안 움직인다 | `collector` `OtlpGrpcMtlsRequireTest` |
| `optional` : 신분증 없는 TLS 손님 통과(tls 칸) · 신분증 손님(mtls 칸) · 다른 기관은 끊김 · **평문은 끊김** | `collector` `OtlpGrpcMtlsOptionalTest` |
| 기본값 `none` : 기존 시험이 그대로 평문으로 통과 | `collector` 기존 110건 |

- 시험용 인증서는 `scripts/certs/make-certs.sh` 를 임시 폴더에 두 번 돌려 만든다
  - 우리 기관 · 다른 기관
  - JVM 이 끝날 때 지운다
  - compose 와 같은 스크립트라 모양이 다를 수 없다
  - `openssl` 이 PATH 에 있어야 한다
- 시험 수 : 수집기 **138건**, 실패 0 (2026-10-13)
  - 다른 모듈은 안 바꿨다

### 조사가 바로잡힌 것 셋 (지우지 않는다)

1. **"끊김 없이 옮길 수 있다" 는 과장이었다**
   - 5절 묶음 6 에 그렇게 적었는데, `optional` 로 올리자 평문 에이전트는 전부 떨어졌다 (2 단계, 연결 0)
   - `optional` 이 봐주는 것은 "TLS 로 왔는데 신분증이 없는 손님" 이지 평문이 아니다
   - 평문 → TLS 는 에이전트 설정을 바꾸고 재시작하는 한 번이 반드시 든다
   - 두 단계의 값은 "끊김 없음" 이 아니라 "빠뜨린 쪽이 조용히 멈추지 않음" 이다
   - 시험(`OtlpGrpcMtlsOptionalTest`)으로 고정했다
2. **"게이지 4" 는 연결이 아니라 에이전트 수여야 맞는다**
   - 에이전트 하나가 신호마다 연결을 따로 열고 로그 연결은 보낼 로그가 생겨야 연다
   - 기동 직후 12, 수집기 재시작 뒤 8
   - 연결 수로는 "넷이 다 붙었나" 를 못 읽어 주소를 묶은 게이지를 더했다
3. **에이전트가 빈 환경변수를 "없음" 으로 보리라는 가정이 틀렸다**
   - 쇼핑몰 compose 에 `OTEL_EXPORTER_OTLP_CERTIFICATE=` 처럼 빈 값을 넣자 네 에이전트가 `Invalid OTLP certificate/key path` 로 멈췄다
   - 그래서 environment 가 아니라 켤 때만 읽히는 `env_file` 로 바꿨다
   - 같은 이유로 `OTEL_EXPORTER_OTLP_ENDPOINT` 를 environment 에 둘 수 없어 그 변수를 뺐다
     - null 항목이 env_file 값을 덮는다 (실측)
