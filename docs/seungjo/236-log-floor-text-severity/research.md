# 리서치 : 로그 하한이 숫자 0 인 레코드를 글자로 판정한다

- 날짜 2026-10-20 / 관련 이슈 [`#236`](https://github.com/2026-techeer-project-team-b/monimo-backend/issues/236) (앞 이슈 `#215` · PR `#228` 머지, ADR `#59` · `#38` ④ · `#55` 되돌림 ③)
- 쓴 도구: 레포 직접 읽기(`collector/filter/LogLevelFilter.kt` · `ingester/transform/LogTranslator.kt` · `common/` · 두 테스트 · ADR `#59`)

> **읽는 순서가 곧 쓰는 순서다.** 1 → 2 를 쓰고 멈춰서 승조가 3 을 묻는다. 답하고 4 를 쓴다.
> 5 를 쓰고 멈춰서 승조가 6 을 묻는다. 답하고 7 을 쓴다. 8 은 승조가 쓴다.
> **3 · 6 · 8 은 사람 차례다.** 비어 있으면 아직 거기까지 온 것이고, 대신 채우지 않는다.

---

## 1. 이번 작업은 무엇을 하는 일인가

- **지금 무엇이 잘못됐나** : 로그 등급은 숫자 칸과 글자 칸 둘로 온다. 수집기는 숫자만 보고 「숫자가 비면 모른다, 남긴다」 로 하고, 적재 처리기는 「숫자가 비면 글자를 읽는다」 로 한다. 그래서 숫자가 비고 글자가 `DEBUG` 인 줄은 수집기를 그대로 지나 `DEBUG` 로 쌓인다
- **그래서 무엇을 만드나** : 수집기도 숫자가 비면 글자를 읽어 하한 아래면 버린다. 글자를 읽는 규칙은 적재 처리기와 **같은 것 하나**를 쓴다
- **안 하면 어떻게 되나** : 하한을 INFO 로 두어도 숫자를 안 채우는 생산자(다른 언어 · 손으로 만든 전송)의 DEBUG 는 `logs` 에 들어온다. `#215` 가 막으려던 홍수가 그 길로는 그대로 열려 있다

| | |
|---|---|
| 건드리는 모듈 · 파일 | `collector/filter/LogLevelFilter.kt`(판정) · `ingester/transform/LogTranslator.kt`(판정을 꺼내 같이 쓴다) · 판정을 둘 곳(`common` 후보) · 테스트 셋(`LogLevelFilterTest` · `OtlpGrpcReceiverTest` · `LogTranslatorTest`) · `LogLevelFilter` 주석 |
| 건드리지 않는 것 | 하한 설정 이름 · 기본값(`monimo.collector.log.min-level` = `INFO`, 비우면 끔) · 숫자가 있을 때의 판정 · ClickHouse `logs` 표 · 별칭 표의 내용(ADR `#59` 그대로) · 헬스체크 거르기 · 샘플링 |
| 이 이슈 범위 밖 (후속) | 하한 설정값에 별칭을 받기(`min-level: WARNING` 같은 것. 지금은 여섯 이름만 받고 나머지는 기동 때 터진다) · 앱별 하한 · 원래 글자 보존(ADR `#59` 되돌림 ①) · 세 거르기(헬스체크 · 샘플링 · 로그 하한) 공통화 |

**조사 들어가기 전에 내가 알던 것 (세 줄)**

- OTel 로그는 숫자(`severity_number`, 1~24)와 글자(`severity_text`)를 따로 들고 오고 둘 다 선택이다. 숫자 0 은 「안 적힘」 이다
- 적재 처리기는 `#144`(ADR `#59`)로 「숫자가 정본, 없을 때만 글자를 별칭 표로」 를 정했다. 수집기 하한은 `#215` 에서 숫자만 보게 짰다
- 우리가 붙이는 OTel Java 에이전트는 숫자를 늘 채운다. 그래서 지금 우리 트래픽에서는 이 갈래가 안 밟힌다

**알고 싶었던 것**

- ① 숫자 0 인 레코드를 **실제로 누가 보내나**. 우리 트래픽 · 쇼핑몰 · `telemetrygen` · 남의 앱 중 어디서 오나
- ② 판정 규칙을 **어디에 하나로 두나**. `common` 에 두면 「공유 모델만 둔다」 는 그 모듈의 약속과 맞나
- ③ 숫자가 **규약 밖(25 이상 · 음수)** 인 레코드는 어떻게 하나. 적재 처리기는 그것도 「숫자 없음」 으로 보고 글자를 읽는다
- ④ 글자로 판정해 버린 것을 **지금 카운터에 어떻게 세나**. 꼬리표 `level` 은 숫자에서 이름을 뽑는데 숫자가 0 이다
- ⑤ 이 변경이 ADR `#59` 와 `#215` 결정 중 **무엇을 바꾸는 것인가**. 새 번호를 달아야 하나

## 2. 작업하기 전에 알아야 하는 것

### 2.1 로그 등급 칸 둘 : 숫자와 글자

- OTLP 의 로그 한 줄(`LogRecord`)에는 등급 칸이 둘 있다
  - `severity_number` : 1~24 의 숫자. 여섯 구간이 네 칸씩이다 : TRACE 1~4 · DEBUG 5~8 · INFO 9~12 · WARN 13~16 · ERROR 17~20 · FATAL 21~24
  - `severity_text` : 생산자가 부르는 이름 그대로인 자유 글자. Logback 은 `WARN`, java.util.logging 은 `WARNING` · `FINE`, Python 은 `CRITICAL`
- 둘 다 **선택**이다. 숫자가 0 이면 「안 적힘(UNSPECIFIED)」 이고, 「아주 낮은 등급」 이라는 뜻이 아니다
- 규약은 「크기를 비교할 때는 숫자를 쓰라」 까지만 말하고, 숫자가 없을 때 무엇을 하라고는 정하지 않았다 (ADR `#59` 근거)

### 2.2 지금 두 모듈이 같은 줄을 어떻게 판정하나

- **수집기** `LogLevelFilter.isBelow` (`#215`)
  ```kotlin
  val number = record.severityNumberValue
  return number != 0 && number < min   // min = INFO 면 9
  ```
  - 숫자만 본다. 0 이면 「무엇인지 모르는 것을 버리면 안 된다」 로 남긴다 (클래스 주석)
- **적재 처리기** `LogTranslator.levelOf` (`#144`, ADR `#59`)
  ```kotlin
  fromNumber(record.severityNumberValue) ?: fromText(record.severityText)
  ```
  - `fromNumber` 는 1~24 만 이름으로 바꾸고 **0 과 규약 밖은 `null`** 이다. 그러면 글자를 별칭 표(`ALIASES`, 24개)로 읽는다. 표에 없으면 빈 글자
- 하한이 `INFO` 일 때 같은 줄이 어떻게 갈리나

  | 숫자 | 글자 | 수집기 (지금) | 적재 처리기가 쌓는 `level` | 맞나 |
  |---|---|---|---|---|
  | 5 | `DEBUG` | 버림 | (안 옴) | 맞다 |
  | 9 | `DEBUG` | 남김 | `INFO` (숫자가 이긴다) | 맞다 |
  | 0 | `DEBUG` | **남김** | **`DEBUG`** | **어긋남** |
  | 0 | `FINE` | **남김** | **`DEBUG`** | **어긋남** (java.util.logging 이름) |
  | 0 | `INFO` | 남김 | `INFO` | 맞다 |
  | 0 | `blah` · 빈 글자 | 남김 | `''` | 맞다 (모르는 것은 남긴다) |
  | 99 | `DEBUG` | **남김** (99 ≥ 9) | **`DEBUG`** (99 는 숫자 없음으로 본다) | **어긋남** (알고 싶었던 것 ③) |

- 즉 **숫자가 이길 때는 둘이 같고, 숫자가 없을 때만 갈린다.** 수집기는 「없음 = 모름」 이고 적재 처리기는 「없음 = 글자를 본다」 다

### 2.3 데이터는 어디로 흐르나

```
앱의 로거 ──(에이전트가 숫자 · 글자를 채워 OTLP 로)──▶ 수집기 :4317
                                                        │
                    OtlpLogsService.export (inbound/otlp/OtlpExportServices.kt)
                        ① 수신 카운터 +N   (거르기 전 숫자)
                        ② LogLevelFilter.drop  ← 여기서 하한 미만을 뺀다  ★ 이번에 고치는 곳
                           └ 버린 수 monimo.collector.dropped{reason=log_level, level=…}
                        ③ 남은 게 0줄이면 Kafka 에 안 보내고 OK 응답
                        ④ 남은 요청을 바이트 그대로 Kafka raw 로
                                                        │
                                                        ▼
                                  적재 처리기 LogTranslator.toRows
                                     levelOf = 숫자 → 없으면 글자(별칭 표) → 없으면 ''
                                                        │
                                                        ▼
                                          ClickHouse monimo.logs.level
```

| 질문 | 답 |
|---|---|
| 버린 줄은 어디에 남나 | 안 남는다. 카운터만 는다 (헬스체크 거르기와 같은 약속) |
| 에이전트는 무엇을 받나 | OK. 버렸다고 알리지 않는다 (에이전트가 재전송하지 않게) |
| 하한을 끄는 법 | `MONIMO_COLLECTOR_LOG_MIN_LEVEL` 을 비운다 |
| 지금 숫자 0 인 줄이 들어오나 | 우리 모듈 · 쇼핑몰은 OTel Java 에이전트라 숫자를 늘 채운다 (`LogTranslator.fromText` 주석). **실측은 아직 안 했다** (알고 싶었던 것 ①) |

### 2.4 `common` 모듈

- 수집기 · 적재 처리기 · API 서버 등이 같이 쓰는 코드 자리다. `common/build.gradle.kts` 첫 줄 주석이 「공유 모델만 둔다. Entity · Repository · Service 금지」 다
- 지금 든 것은 Kafka 쪽 둘뿐이다 : `common/kafka/RawHeaders.kt`(raw 메시지 머리말 이름) · `RawSignal.kt`(신호 종류)
- `opentelemetry-proto` 를 `api` 로 내므로, `common` 에 둔 코드는 `LogRecord` 를 그대로 받을 수 있다
- 수집기 · 적재 처리기 둘 다 `implementation(project(":common"))` 이다
- 별칭 표 같은 「값의 뜻을 정한 표」 가 「공유 모델」 에 드는지는 이 문서가 정할 일이다 (알고 싶었던 것 ②)

### 2.5 지금 테스트가 고정해 둔 것

- `LogLevelFilterTest` : 숫자 0 레코드는 **남는다**를 고정한다 (`listOf(info, warn, 0)` 기대). 이번 변경은 이 기대를 「0 + 판정되는 글자면 판정대로」 로 바꾼다
- `OtlpGrpcReceiverTest` (`#215` 리뷰로 더해짐) : DEBUG 만 보내면 raw 에 새 메시지가 없고 수신 카운터는 늘어난다 · DEBUG + INFO 면 INFO 만 남는다. 둘 다 숫자로 등급을 준다
- `LogTranslatorTest` (`#144`) : 별칭 표 · 경계값 · 「숫자가 규약 밖(99) + 글자면 글자로」 를 고정한다. 판정을 옮겨도 이 기대는 그대로여야 한다

### 2.6 자주 헷갈리는 것

| 헷갈리는 것 | 실제 |
|---|---|
| 숫자 0 은 TRACE 보다 낮은 등급이다 | 「안 적힘」 이다. 등급이 아니다. 그래서 숫자만 보면 「모름」 이 맞다 |
| 수집기가 글자를 보면 ADR `#59` 와 어긋난다 | `#59` 는 「숫자가 정본, **숫자가 없을 때만** 글자」 다. 수집기가 그 순서를 그대로 따르면 오히려 맞춰진다 |
| 「모르는 것은 버리지 않는다」 가 깨진다 | 별칭 표에 있는 글자는 「아는 것」 이다. 표에 없는 글자 · 빈 글자는 지금처럼 남긴다 |
| 이건 우리 트래픽에서 지금 생기는 문제다 | 우리가 붙인 에이전트는 숫자를 채운다. 숫자를 안 채우는 생산자가 붙을 때 열리는 길이다 (`#55` 되돌림 ③ 의 「남의 앱」) |
| 버린 걸 셀 때 등급 이름은 숫자에서 뽑으면 된다 | 지금 `levelNameOf` 는 `(숫자 - 1) / 4` 로 뽑는다. 글자로 판정해 버린 줄은 숫자가 0 이라 이 식으로는 이름이 안 나온다 (알고 싶었던 것 ④) |
